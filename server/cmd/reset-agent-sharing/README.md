# 历史智能体共享权限回收操作手册

这是一次性、显式执行的维护工具，不会被后端启动、数据库迁移、开发环境初始化或每日同步自动调用。只发布新版代码不会回收历史共享。现有验证只使用过独立测试集群，不代表目标环境已经执行。

## 1. 范围和执行前提

- 处理目标数据库中**所有工作区**的 `kind='user'` 智能体，包括已归档智能体；当前没有只处理某个工作区的参数。系统智能体排除在外。
- 将 `permission_mode` 和兼容字段 `visibility` 设为 `private`，删除对应的 `agent_invocation_target` 共享授权；已经完全私人且没有授权记录的智能体不更新。
- 保留智能体、所属人、运行时、项目、任务、会话、文件等业务数据，不删除或重置数据库，不变更智能体所属人。
- 无所属人的智能体会在预览中计数并列入快照。改为私人后无人能以所属人身份访问，需要先核对处理方案；工具不会自动指派所属人。
- 需要配合包含严格本人访问校验的新后端：工作区 owner、admin 身份不能绕过私人限制。新建默认私人和共享风险弹窗也应完成部署。
- 已运行的任务和本机进程不会被回收工具停止；队列中尚未投递的工作在投递时重新检查权限。若要求立即停止在途工作，需另行明确停止范围和执行方案，不能依靠本工具。
- 回收完成后，用户仍可在风险提示后主动重新共享。**不将此工具加入启动脚本或定时任务**，避免反复撤销用户后续主动共享。

## 2. 先在预发布完整演练

使用预发布自己的数据库连接，按“预览 → 审核 → 执行 → 验证”完整演练，记录智能体数量、锁等待、执行耗时和客户端刷新表现。演练不能使用日常开发数据库的初始化或清理脚本。

正式执行前核对目标数据库、服务器及所有工作区范围，确认常规数据库备份可恢复。权限快照只保存本工具涉及的权限记录，**不能替代数据库备份**。

## 3. 部署并安排维护窗口

1. 通过现有发布流程部署兼容的前后端及所需迁移，确认旧后端实例已退出，不会继续按旧规则处理访问。
2. 根据预发布演练安排短暂维护窗口，减少智能体编辑、共享及运行状态写入，再连续进行预览和执行。不要未经安排直接停止后端或运行环境。
3. 工具比较完整快照，其中包括 `updated_at`。运行状态更新、新增智能体或授权变化都可能使预览过期，需要重新预览；不是只比较影响数量。
4. 执行时取得 `agent`、`agent_invocation_target` 的 `SHARE ROW EXCLUSIVE` 表锁，相关写入会等待，普通查询通常仍可继续。锁等待最多 5 秒，单条 SQL 最多 30 秒；30 秒不是整个工具的总时限。事务内逐个更新并持久保存执行记录，耗时取决于数量和磁盘等条件，不承诺零影响。

## 4. 准备工具及安全目录

在仓库 `server/` 下构建，不连接数据库：

```sh
go build -o /private/tmp/reset-agent-sharing ./cmd/reset-agent-sharing
```

下面命令以 `/private/tmp/reset-agent-sharing` 为示例；正式环境应使用在目标服务器或容器可运行的对应构建，替换成实际工具路径。

由部署环境安全注入明确的 `DATABASE_URL`；工具不会读取 `.env`，也没有默认数据库。不要把连接密码写进聊天、操作手册或日志。`--expected-database` 必须填写准确数据库名，不能沿用示例或猜测。

提前准备只有执行人员可访问的现有目录。每轮使用全新文件名；快照和执行记录以 `0600` 创建，已有文件不会覆盖，并在成功写入后同步到磁盘。材料包含用户 ID、智能体名称和授权信息，应受控保存。输入文件须为普通文件，最大 32 MiB；演练发现超过上限时先评估工具，不跳过快照校验。

## 5. 生成预览并审核

```sh
/private/tmp/reset-agent-sharing --mode preview \
  --expected-database '<database-name>' \
  --snapshot '<protected-directory>/sharing-preview.json'
```

此步骤不修改数据库权限，只读取数据库并生成本地快照。核对输出中的数据库名、服务器地址/端口、用户智能体总数、待修改数、无所属人数、排除的系统智能体数，以及快照中的完整智能体和授权明细。

保存输出的 SHA256。将具体目标和影响范围交给执行确认人核对，获得本次执行确认后再进入下一步；不向全部工作区 owner 自动发送通知。

## 6. 执行一次回收

```sh
/private/tmp/reset-agent-sharing --mode apply \
  --expected-database '<database-name>' \
  --snapshot '<protected-directory>/sharing-preview.json' \
  --sha256 '<reviewed-preview-sha256>' \
  --receipt '<protected-directory>/sharing-reset-receipt.json'
```

执行会再次检查数据库名、服务器信息、快照校验值及当前完整状态，锁定相关表后在一个事务中回收权限。执行前后记录成功落盘后才提交；落盘失败则回滚。

| 结果 | 下一步 |
| --- | --- |
| 正常提交 | 保留快照和执行记录，进入验证 |
| 数据库或 SHA256 不匹配 | 停止，核对目标和文件，不绕过校验 |
| 预览过期 | 排查期间写入，用新文件名重新预览、审核 |
| 表锁超时 | 本次不修改权限，调整维护窗口后重新预览 |
| 提交结果不明确 | 保留执行记录，核对数据库实际状态；不要盲目重试或直接回退 |

## 7. 验证结果

在用户重新共享之前，使用目标环境的只读查询方式检查以下结果。两项均应为 `0`；仍需结合执行记录核对系统智能体、所属人及其他业务数据未改变。

```sql
SELECT count(*) AS non_private_user_agents
FROM agent
WHERE kind = 'user'
  AND (permission_mode IS DISTINCT FROM 'private'
       OR visibility IS DISTINCT FROM 'private');

SELECT count(*) AS remaining_user_agent_grants
FROM agent_invocation_target t
JOIN agent a ON a.id = t.agent_id
WHERE a.kind = 'user';
```

刷新或重新打开客户端，实际验证：

- 所属人能查看和调用自己的私人智能体；原共享对象、其他成员、工作区 admin 和 owner 不能绕过限制调用。
- 新建智能体默认私人；全工作区公开和指定成员共享都会显示风险提示；取消不保存，确认继续后按原共享逻辑保存。
- 原共享对象的待投递工作因失去权限被拦截；已运行工作按事先约定单独处理，不将“回收完成”解释为“所有进程已停止”。
- 独立 SQL 工具不会主动推送客户端实时更新，界面刷新不能代替后端访问校验。恢复使用前完成真实调用验证。

## 8. 回退限制

回退会恢复原来的公开及共享授权，风险也会恢复。优先排查权限和所属人问题；确有必要时，审核恢复范围后显式执行：

```sh
/private/tmp/reset-agent-sharing --mode rollback \
  --expected-database '<database-name>' \
  --receipt '<protected-directory>/sharing-reset-receipt.json'
```

回退要求当前全部用户智能体及授权状态与执行记录中的回收后状态完全一致。后续新增智能体、授权、记录修改或 `updated_at` 更新都会导致拒绝，防止覆盖后续操作；因此不能承诺正常运行后随时一键回退。

满足条件时恢复原权限及授权 ID、目标、创建人和创建时间；智能体 `updated_at` 记录回退时间。保留快照和执行记录直到发布验收结束，并按内部权限数据保存要求归档。
